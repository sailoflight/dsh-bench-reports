# 03 · Harness 双任务协议对比(调研 / 建模)

> 启动:2026-09-02 · **状态:进行中**(记录表未完成,结果与评定未出)
> 本报告仅公开**协议与设计**,不包含任何结果性结论。
> 目标模型:gpt-5.6(单模型、单 effort 控制变量)

## 一、问题与设计

检验 **harness 本身对真实任务完成质量的影响**(token 只是其一)。为此构造
**两类真实、非 toy 的任务**,在两个环境下逐字一致地执行:

| 环境 | 说明 |
|---|---|
| dsh | DeepSeek Harness |
| 对照 CLI | 另一独立 agent CLI 环境 |

**逐字相同请求(方案内 md5 校验一致)**:同一方案的 dsh 轮与对照轮拿到完全一样的自然语言请求,
像同一个人真的来提需求;完成方式与呈现形式交给 agent 自决——只有这样才能看出 harness 影响,
而不是提示词/模板差异。

### 方案 A:行情调研(信息真实性 + 决策支持)

- 任务:对一组耗材品类(5 种材料,1 kg 规格)做市场行情调研,输出可支撑购买决策的结论。
- 人工评定:信息是否真实可核、分级/代表是否合理、能否支撑决策。

### 方案 B:未知域浏览器建模(能力边界探测)

- 任务:按自然语言需求,在陌生专业领域(专有参数化建模环境 + 未知建模语言,浏览器 MCP 操作)
  从零构建一个高难度单件(尺寸/孔/交错槽特征俱全、要求实心一体),agent 此前从未建过该特征。
- 人工评定:尺寸达标 / 特征齐全 / 单件可用 / 建模正确(可打开建模环境复核)。

## 二、协议要点(防污染设计)

1. **四份隔离工作区**(2 环境 × 2 方案),互不读写;每轮独立、严格串行执行。
2. 控制变量:模型统一 gpt-5.6、effort 统一 high、请求文本方案内逐字一致(md5 校验)。
3. **token 读数分口径**:dsh 轮用网关 /usage 前后差;对照 CLI 轮由该环境直读——
   两口径分别标注,不做混用比较。
4. 方案 B 轮间清理:两轮 B 共用同一浏览器/账号 profile,每轮结束后产物改名打标,
   且只在对应轮 agent 退出后操作,防止轮间污染。
5. 产出质量一律**人工评定**,不用 agent 自评。
6. 浏览器 MCP 经统一中继桥,不混用旧直连通道。
