# 02 · Token 消耗对比:多 agent 修复同一真实缺陷

> 时间:2026-08 封档 · 模型:同一底层模型(控制变量)经统一网关
> 任务:一个**真实生产缺陷修复任务**(语料取自内部工程,不在本仓分发;以下仅给方法与聚合结果)

## 一、问题与设计

同一模型下,三个 agent 产品(codex / Claude Code / dsh)分别**独立修复同一缺陷**,
对比两件事:**token 消耗** 与 **修复质量**。

- 每个 agent 在完全隔离的工作区拿到逐字相同的任务(仅给缺陷现象,不泄露参考答案),
  禁止访问版本库/工作区外/查找答案,允许联网(agent 原生能力)。
- 修复正确性 = 启发式判定(命中参考修复的变更特征)+ **人工复核**双保险。
- token 读数取网关统一口径,不混用自报数字。

## 二、结果

### 修复质量(参考命中 + 人工复核)

| agent | 命中率 | 人工复核 |
|---|---|---|
| dsh | 12/12(100%) | 与参考修复一致(exact match) |
| codex | 5/12(42%) | 功能等价,实现不同,复核通过 |
| claude | 4/12(33%) | 策略不同;复核判定**未触及根因**,不能阻止缺陷复现 |

### Token 消耗(同一任务)

| agent | 请求数 | 缓存读(M) | 未命中输入(k) | 输出(k) | 缓存率 |
|---|---|---|---|---|---|
| dsh | 52 | 4.10 | 103 | **17** | 97.6% |
| codex | 91 | 9.71 | 191 | 62 | 98.1% |
| claude | 95 | 9.36 | 153 | 88 | 98.4% |

示例加权费用(输出=1 / 未命中输入=0.25 / 缓存=0.025 每 token 的相对权重):

| agent | 加权费用 | 相对 dsh |
|---|---|---|
| dsh | 145.3 | 1.0× |
| codex | 352.6 | ≈2.43× |
| claude | 360.2 | ≈2.48× |

## 三、结论

1. **消耗与质量同向最优**:最低消耗的一方(dsh)反而 100% 命中参考修复;
   另两方消耗 ≈2.4–2.5×,质量分别为功能等价(42%)与未触及根因(33%)。
2. **费用大头是「未命中输入 + 输出」**:缓存读虽占各自输入 ~98%,但单价极低,不是费用驱动。
   - 输出(通常最贵):claude 88k > codex 62k > dsh 17k(claude ≈ dsh×5.2)
   - 未命中输入:codex 191k > claude 153k > dsh 103k
3. **单任务即出分化**:请求数与输出量差距(1.8–5.2×)来自 agent 各自的迭代习惯
   (重读/重试 vs 一步到位),提示 harness 设计对"浪费型重读"有真实优化空间。

## 四、局限

- 单任务 × 单模型 × 单网关口径;命中判定为启发式 + 人工复核,非端到端回归。
- 加权费用用示例单价,精确金额以实际账单为准(趋势结论与单价无关)。
- 三类 agent 属不同产品,差异是"产品整体"差异,不单独归因于 harness。
