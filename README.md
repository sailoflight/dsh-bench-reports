## 核心结论(跨组摘要)

1. **正确率不是差异维度。** 01 组:同模型下 6 预设 × 量化题全部通过(正确率零区分);
   预设改变的是 **token 经济、墙钟与思维链风格**,不是对错。
2. **省 token ≠ 省时间;省时间 ≠ 代码更好。** 01/02 组反复出现同一现象:
   工具受限/低 token 一侧墙钟更慢(往返开销),但实现往往更朴素更快(ms 级);反之完整工具侧
   快但推理量 2–6× 放大。选型应按"计划者/执行者"分工,而非单一指标。
3. **修复类任务上,低 token 不等于低质量。** 02 组同一缺陷修复中,消耗最低的一方反而
   命中参考修复(100%),消耗最高的两方分别功能等价(42%)与未触及根因(33%,人工复核判定)。
4. **对比协议本身要防污染。** 03 组强调:逐字相同请求 + 隔离工作区 + 人工评定 + 统一读数口径,
   否则 harness 差异会被提示词/口径噪声淹没。

## 方法与口径(三组通用)

- 全部任务为**可机判或人工可复核**的量化口径;通过率/命中率为权威判定,不采用主观自评。
- token 读数一律来自网关/面板读数,标注口径,不混用。
- 03 组仍在进行(记录表未完成),当前仅公开协议与状态,无结论。

## 局限(请如实解读)

- 01 组题目偏算法实现类,不覆盖 Web 检索、长文档、多 agent 编排等场景;
- 02 组为单任务 × 单模型,命中判定为启发式(参考修复新增行)+ 人工复核,非端到端回归;
- 03 组结果未出,公开内容不代表任何结论;
- 各数值均为特定日期/配置下的实测,价格与模型配置变化会改变绝对数字,趋势结论更可靠。
